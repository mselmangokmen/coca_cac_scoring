# Segmentation-free CAC scoring and calcium localization on Stanford COCA

Code accompanying the manuscript *Segmentation-Free Coronary Artery Calcium Scoring from Frozen
Self-Supervised CT Features*. It runs the study's pipeline end to end on the public **Stanford COCA**
dataset with two **publicly available, frozen** encoders, Curia and MedDINOv3:

1. reading the original DICOM series and the released OsiriX calcium contours;
2. recomputing the reference Agatston score of the gated arm from those contours;
3. patient-level train / test splits of the gated and the non-gated arm;
4. frozen-encoder feature extraction (the 32 highest-attention patches of every slice);
5. training the additive scoring head on volume-level Agatston scores only, and evaluating it;
6. the scoring metrics (CAC-DRS kappa with bootstrap intervals, accuracy, AUROC, MAE, ICC, Bland-Altman);
7. the localization analysis of the encoders' attention (pointing game, lesion recall, top-32 coverage,
   false-alarm rate, class-token probe) at every layer;
8. end-to-end inference with timing, and the per-patch decomposition of a prediction.

No private data and no model trained on private data is used or needed. The encoders are never updated:
only the scoring head (about 2.6 x 10^5 parameters) is trained, on COCA.

## Setup

**Environment.** Python >= 3.11 and a CUDA GPU (about 10 GB of memory is enough). Install PyTorch for
your CUDA version (https://pytorch.org), then

    pip install -r requirements.txt

To reproduce the reported numbers bit for bit, use the pinned versions instead (see "Results"):

    pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu129
    pip install -r requirements-exact.txt

**Data.** Stanford COCA (Coronary Calcium and chest CTs), from the Stanford AIMI Center:
https://aimi.stanford.edu/datasets/coca-coronary-calcium-chest-ct. The scripts expect the release root,
holding `Gated_release_final/` (`patient/<pid>/<series>/*.dcm`, `calcium_xml/<pid>.xml`) and
`deidentified_nongated/` (`<pid>/[<series>/]*.dcm`, `scores.xlsx`).

**Encoders** (published weights, used as released):

    # Curia (gated model: accept its licence on the Hugging Face page first)
    hf download raidium/curia config.json model.safetensors --local-dir weights/curia
    # MedDINOv3, and the DINOv3 model code it needs
    hf download ricklisz123/MedDINOv3-ViTB-16-CT-3M model.pth --local-dir weights/meddinov3
    git clone https://github.com/facebookresearch/dinov3 dinov3

The runs below used files with these SHA-256 checksums: Curia `model.safetensors`
`fbf59575cf2b7a780d51fde57c3dc6d99d85c0f99ed31147994d54aebf90df32`, MedDINOv3 `model.pth`
`492b2b96c00e9d3b93ba3b07a8d387aa2196b5e04698378fcc23049b447966d2`, DINOv3 code at commit `6876159`.

## Running

    DATA=/path/to/coca bash run_all.sh

or step by step (see `run_all.sh` and each script's `--help`):

    python scripts/extract_features.py --encoder curia --weights weights/curia --cohort gated \
        --data-root $DATA --split-csv splits/coca_gated_split.csv
    python scripts/train_head.py --features outputs/features/curia_L7/coca_gated.npz \
        --split-csv splits/coca_gated_split.csv --out outputs/heads/curia_L7/coca_gated
    python scripts/pointing.py --data-root $DATA --side test --encoder curia=weights/curia
    python scripts/predict.py --encoder curia --weights weights/curia \
        --head outputs/heads/curia_L7/coca_gated/head.pt --series $DATA/Gated_release_final/patient/<pid>/<series>

Everything is written under `outputs/`. On one NVIDIA RTX A6000 the whole pipeline takes about 35 minutes,
and about 30 more with the layer-12 comparison (step 5 of `run_all.sh`).

## Method

**Reference scores.** Non-gated: Stanford's own per-patient scores (`scores.xlsx`). Gated: the release
has no scores, so they are recomputed from the annotators' contours. Each contour (a hollow outline) is
closed, filled and dilated by 2 px; on each slice, the connected components (8-connectivity) of
`annotated AND HU > 130` are lesions; lesions of 1 mm^2 or less are discarded; each lesion adds its area
(mm^2) times the density weight of its peak HU (1: 130-199, 2: 200-299, 3: 300-399, 4: >= 400). A
cross-check without dilation, one lesion per contour and HU >= 130, reproduces the annotators' own
OsiriX area and peak values and agrees closely with the reference (median ratio 0.999, the same risk band
for 440 of 443 patients; column `cross_check` of `data/coca_gated_reference.csv`). Of the 449 patients with
both a series and a contour file, 5 cannot be read and 1 has a contour outside its slice stack, which
leaves **443 gated patients**. The non-gated arm has **205 scored patients** with a series.

**Splits.** Per arm, patients are grouped by the CAC-DRS band of their reference score (<=10, 11-100,
101-400, >400), each band is shuffled with `numpy.random.RandomState(42)` and 80% of it goes to train.
Gated: **354 train / 89 test**. Non-gated: **165 train / 40 test**; this is the split used in the
manuscript. Every patient contributes one series.

**Input and features.** Each axial slice is min-max normalised to [-1, 1] over its full field of view
(no HU window). The frozen encoder is read at a fixed layer (Curia 7, MedDINOv3 11: the layers at which
each encoder's attention localises calcium best in the manuscript's development data; `scripts/pointing.py`
reports every layer on COCA). Per slice the 32 patches with the highest class-token attention (mean over
heads) are kept, with their attention values renormalised by a softmax over those 32.

**Scoring head.** For slice i and kept patch k, a shared MLP maps `[feature | s_x | s_y | attention]`
to a non-negative contribution z_ik (softplus); the slice score is s_i = sum_k a_ik z_ik and the volume
prediction is (t/3) sum_i s_i, with t the slice thickness in mm. The prediction is therefore exactly the
sum of the patch contributions c_ik = (t/3) a_ik z_ik (`scripts/predict.py --save-maps`). Training uses
only the volume-level score: Huber loss on log(1 + score), volumes weighted by 1 + log(1 + reference),
AdamW (learning rate 1e-3, weight decay 1e-4), cosine schedule, 16 volumes per batch, 100 epochs, seed 42,
no early stopping and no model selection. The test side is read only after training.

**Scoring metrics** (per patient, on the test side): linearly weighted Cohen's kappa over the four
CAC-DRS bands with a 95% patient-level bootstrap interval (20,000 resamples), accuracy, AUROC for a
reference above 10, MAE, and on log(1 + score) ICC(A,1) with a bootstrap interval, R^2 (squared Pearson
correlation) and Bland-Altman bias with 95% limits of agreement.

**Localization** (gated test side; `coca_cac/localization.py`). The pool holds every calcium-bearing
slice (non-empty calcium mask, as defined for the reference score) of the test patients and, per patient,
as many calcium-free slices as it has calcium-bearing ones, nearest in slice position. On the encoder's
32 x 32 patch grid, a patch is a calcium patch when it contains a calcium pixel. Pointing: the
highest-attention patch is a calcium patch. Lesion recall: with n lesions on a slice, the fraction hit by
the n highest-attention patches. Top-32 coverage: the fraction of a slice's calcium patches among its 32
highest-attention patches, the head's patch budget. False alarm: the fraction of calcium-free slices with
at least one thresholded candidate at lesion sensitivity 0.8. CLS AUROC: a logistic probe on the class
token, 5-fold patient-grouped cross-validation. Baselines: peak HU per patch, and a uniform map.

## Results

One run of `run_all.sh` on one NVIDIA RTX A6000 with the versions of `requirements-exact.txt`. The output
files are in `results/` (metrics, reports, per-patient test predictions, figures and the eight trained heads,
which `scripts/predict.py` can use directly).

**Scoring, test side, per patient.** Heads trained on the train side of the same arm; 95% intervals in
brackets.

| gated | MedDINOv3 (L11) | 354 / 89 | 0.711 [0.592, 0.814] | 0.742 | 0.777 | 147.0 | 0.757 [0.605, 0.881] | +0.32 [-2.33, 2.97] |

With L12 features kappa and ICC are lower for both encoders in both arms.

**Inference time** (`scripts/predict.py`, 50 gated volumes, median 46 slices, files in
`results/timing/`): per volume, median, the encoder takes 0.94 s with Curia and 1.09 s with MedDINOv3
(fp32, 8 slices per forward pass) and the head 2 ms. Reading the DICOM series took 0.09 s here because
the files were in the operating system's cache; from disk it depends on the storage.

**Relation to the manuscript.**
- Non-gated arm, Curia: the manuscript's result is reproduced exactly (kappa 0.660, 0.476-0.805;
  accuracy 0.650; AUROC 0.897; MAE 104.4; ICC 0.709). The feature cache is bit-identical to the one of the
  study's own pipeline, and the 40 per-patient predictions are the same.
- Gated arm: the reference scores are those of the manuscript (443 patients, 22,695 slices), and the Curia
  features are bit-identical to the ones the manuscript's gated transfer experiment used. In the
  manuscript the gated arm is used only to test a head trained on the study's private cohort; the gated
  head trained here, on COCA itself, and the localization analysis on COCA are additions of this
  repository and are not reported in the manuscript.

**Other library versions.** With `requirements.txt` resolved to newer versions (tested: torch 2.6.0,
transformers 5.22.1, numpy 2.4.6, pandas 3.1.1, scikit-learn 1.9.1, opencv 5.0) the reference scores, the
splits, the gated MedDINOv3 row and every pointing value are unchanged. With these versions a small
fraction of the features comes out slightly different (0.4% of the Curia feature values), which moves the
other rows slightly: gated Curia kappa 0.782 [0.680, 0.870] (accuracy 0.798, ICC 0.774); non-gated Curia
kappa 0.660, AUROC 0.900, ICC 0.716; non-gated MedDINOv3 kappa 0.747, AUROC 0.937, ICC 0.793; CLS AUROC
0.928 (Curia) and 0.793 (MedDINOv3). The layer-12 comparison was run with `requirements-exact.txt` only.
Use `requirements-exact.txt` to reproduce the numbers above bit for bit.
